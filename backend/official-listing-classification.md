# 公式掲載状態と販売状態

公式掲載状態は、対象VersionKeyの商品ページが公式サイトで確認できるかを記録する。販売状態は商品の取扱いを記録する。更新は別々に判断し、片方の観測だけで他方を上書きしない。

| 公式掲載状態 | 採用条件 |
| --- | --- |
| 未確認 | 調査範囲が十分でない、接続や検索結果を確認できない、または同一商品か確定できない。 |
| 掲載中 | 日本・フランス・英語公式のいずれかで、対象と同一の商品ページを現在確認できる。確認した市場を根拠に残す。 |
| 公式掲載なし | 対象市場を調査し、現在の商品ページと同一商品の過去掲載履歴のいずれも確認できない。 |
| 公式掲載終了 | 同一商品の旧公式商品ページを資料で確認でき、現在は旧URLと移転先の両方を調査しても掲載を確認できない。 |

同一性はVersionKeyを起点に、名称、REF、商品説明、販売形態、リダイレクト先や言語別ページを照合する。REFだけが一致する別商品や、同名でも限定品・異なるパッケージのページは、同一商品と確認できるまで候補に留める。旧URLが新URLへ移転し商品が一致すれば掲載中。検索結果の欠落、単発の404、403、タイムアウトは掲載終了の根拠にしない。

根拠には、調査日時、対象市場、検索語・REF、確認したURLと結果、同一性の照合内容、過去掲載に用いた資料とその日付を残す。「公式掲載なし」「公式掲載終了」は根拠付きの確認候補として扱い、既存の「掲載未確認」や「未掲載」を一括変換しない。従来値からの移行は、それぞれに根拠が揃った時点で行う。

販売中、入荷待ちなどの既存状態は維持する。「終売推定」は、複数市場での公式調査と、季節・限定・一時休止・URLやREFの変更を検討した根拠が揃う場合の確認候補。「終売確定」は、対象商品を特定できるメーカーの販売終了通知など直接的な資料がある場合に限る。掲載終了でも、販売状態は独立して確認する。

## 調査例

- T2215-B01「THÉ DE LA BONNE ÉTOILE」。現在の公式名・URLの空欄を確認。日・仏・英の公開検索で同一商品の現行ページ、旧URL、別REFとの確実な対応を確認できていない。フランス公式の2023年価格表からは同じ番号に別名の商品候補が出る。これは照合上の注意点であり、対象Versionの旧掲載根拠にしない。
- T935-B01「YIN YANG」。現在の公式名・URLの空欄を確認。日・仏・英の公開検索では対象版に結び付く現行・旧公式商品ページや別REFを確認できていない。

両方とも、現段階の調査判定は「未確認」。公式サイト内検索の一部は検証できていないため、検索結果だけで「公式掲載なし」「公式掲載終了」「終売推定」「終売確定」へ進めない。これは調査方針の記録であり、Master上の状態は既存値を保持する。

## 公開準備版の実装境界

- 標準4分類は未確認／掲載中／公式掲載なし／公式掲載終了。互換用の旧値「未掲載」は読み取り・表示ともそのまま保持し、否定分類へ変換しない。旧「掲載未確認」や未知値は表示上未確認とするが保存値を変えない。
- sales-state.jsで表示と表示範囲を扱い、掲載と終売推定／終売確定を独立したバッジで表示する。旧未掲載の買い物／過去範囲は維持。「旧版」の推定には公式掲載終了と同一Primaryの別Versionの掲載中を要求する。
- 公開PWAは既存のMFSalesState.badges()を使えるので、公開変更はsales-state.jsとservice-worker.jsのキャッシュ名だけ。index.html、app-config.js、research-request.js、未公開カード／検索UIは公開対象外。
- 純粋な分類処理をbackend/official-listing.gsに分離。観測からread-only候補を返すだけで、Sheet更新や定期実行、公開APIの書込routingを持たない。
- 観測はVersionKey完全一致、同一性の根拠、調査日、公式URLの確認が必要。否定分類はJP/FR/ENすべてのアクセス可能な検索・カタログ・商品ページ・移転先・別REF調査を要求し、人間確認候補として返す。「公式掲載なし」は過去掲載も同一商品がない確認、「公式掲載終了」は同一Versionの過去公式掲載資料と現在の旧URL／移転先確認が必要。403・単発404・検索結果不足から決定しない。
- 更新候補は公式掲載状態と独立列「公式掲載根拠／出典」だけ。販売状態、従来の販売状態根拠／出典、公式未掲載確認開始日は上書きしない。
- GAS mainの限定変更はteaData APIの新根拠列空文字fallback、公式掲載状態の入力規則分岐の2箇所のみ。受付routing・image-intent・hash・receipt・worker・既存販売状態処理は変更しない。
- ローカルに残る未コミットの販売状態拡張や初期化ツール、カードUI等は今回の分類commit／releaseへ含めない。GAS v97に存在しない販売状態拡張を本番へ追加しない。
- 新分類の値を実Masterへ自動設定する機能は含めない。今回の移行では既存値・T2215/T935・履歴・キューを書き換えない。個別の根拠と承認が揃った後の新分類適用は別工程。
